## Safety and recovery

Only API, worker, web and supervisor services belonging to the explicitly configured project are eligible. Database containers are excluded. Stopped containers are reported, never started. Docker restart policy remains responsible for process crashes. Two unhealthy observations are required before a health-triggered restart. In observation-only mode, a second consecutive unhealthy observation reports intervention and exits nonzero; it never restarts the container. A subsequent healthy observation clears the failure counter. Restart reservations persist before dispatch, are keyed by project and service across container replacement, and are limited to three per hour with a five-minute cooldown. A later healthy observation records recovery verification without resetting the hourly budget. A successful restart command is only pending verification, never proof of health. Missing essential services or an exhausted restart budget require intervention. Missing or stuck-starting Docker health probes require intervention after ten minutes; they never trigger an automatic restart on that evidence alone. Docker health does not establish authenticated workflow health; provider and user-facing behavior need separate verification.

The runner takes a nonblocking exclusive state lock. Invalid state or Docker inspection errors fail closed. State contains service health metadata and restart timestamps only, not environment variables, message content, tokens or container logs. Keep the state directory private and persistent across host reboots.

During a deployment drain, checking active runs and locked Graphile jobs alone does not account for notification submissions performed by the reconciler. Inspect pending, preparing, submitting and uncertain notification intents before and after stopping workers, allow a bounded graceful stop, and verify the worker actually exits and job locks settle. A stop timeout can interrupt a provider request; retain an uncertain result instead of replaying it. Graphile workers may begin processing jobs before health readiness, so post-start checks are not a startup barrier. These observations do not by themselves prove external-provider drain.

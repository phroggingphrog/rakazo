# Why
Persistent runs already exist, but operational completion does not prove external outcomes and recovery policies do not consistently distinguish invalid authentication from transient failure. Users need unattended tasks with accurate evidence and intervention, without replacing the existing runtime.

# What Changes
- Harden existing Task/Run/ExternalEffect recovery with durable intervention, bounded retry policy and explicit verification.
- Configure conservative mail, read-only calendar and provenance-aware subscription workflows using existing routines and integrations.
- Extend shared monitoring contracts and existing host supervision; validate mobile approvals and delivery.
- Protect deterministic proactive wake stages from configurable judge ordering.
- Add controlled failure coverage, rollback documentation and a real seven-day observation protocol.

# Capabilities
## New Capabilities
- `verified-task-execution`: durable lifecycle, dependency intervention, effect reconciliation and evidence.
- `workspace-monitoring`: permission-constrained scheduled mail, calendar and subscription checks.
- `execution-operations`: shared monitoring, deterministic infrastructure recovery and observation reporting.
## Modified Capabilities
None in the existing canonical spec inventory.

# Impact
Existing PostgreSQL schema, worker/adapters, shared contracts and applicable clients; additive migrations only and no new database, orchestrator or required vendor. Runtime and deployment remain compatible with existing Pi and Graphile infrastructure. Production changes follow tested rollout with a shared image pin and rollback. Private deployment details and account data stay out of tracked artifacts.

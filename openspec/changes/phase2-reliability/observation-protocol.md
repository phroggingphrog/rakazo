## Measurement boundaries

Record the released revision, shared image digest, schema migration versions and exact start timestamp with timezone in the existing task record. Define seven consecutive 24-hour windows from that timestamp; use explicit-offset timestamps as window_start/window_end for observation-query.sql through the existing database administration path and set `ON_ERROR_STOP=1`. The query rejects empty or reversed windows and timestamps without offsets, uses a repeatable-read read-only transaction, and emits aggregate statuses only. Rakazo stores these timestamps as UTC without a timezone; the query converts the offset-aware bounds to UTC before comparing them, independently of the database session timezone. A completed ledger status is not proof of a successful external outcome.

The run tables report the current state of runs **created** in the window, at the time the query is run. They are not a count of transitions or completions that happened during the window. A run finishing later can change a previously reported cohort; record the query timestamp and label any later remeasurement. An empty result or zero counts only the rows visible in the queried ledger, not missing scheduled occurrences. The notification table is a separate cohort of intents created in the window, not all notifications for the run cohort; its acceptance and receipt values do not prove device display.

Treat a missing table or column, database error, nonzero `psql` exit, or missing `COMMIT` as an unavailable report. Do not use partial output from a failed query. Run with an authorized role that can see the complete intended cohort; otherwise record the visibility limit and do not treat hidden rows as zero.
